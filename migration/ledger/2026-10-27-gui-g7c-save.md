## 2026-10-27: GUI G7c: the save section

The overlay that names a preset, or a wavetable, before saving it: a port
of `SaveSection` (`vital/src/interface/editor_sections/save_section.cpp`).

**Overlay** (`port/crates/gui/src/sections/save_section.rs`)

- `SaveLayout` is `getSaveRect` and `setSaveBounds`: the name and author
  fields, the nine style buttons in rows of three, the comments field, the
  NAME, AUTHOR, STYLE and COMMENTS labels, and Cancel and Save, all from
  upstream's constants. `setSaveBounds` pads vertically by `kPaddingX`, and
  the port keeps that. A file's box (`saving_preset_` false) is shorter and
  has no styles or comments. `OverwriteLayout` is `setOverwriteBounds`.
- It opens with the synth's preset name, comments and style
  (`setVisible`). The author field starts as the config's `"author"`
  (`LoadSave::getAuthor`) and keeps its text between openings, as the
  component does. The name field takes the keyboard with the caret after
  its text (`grabKeyboardFocus`, raising the window focus request for FL
  Studio). That happens a frame after the click that opened the section,
  because a field drops focus on a click elsewhere.
- The fields use the light face at 0.6 of their height in the preset text
  colour (`applyFontToAllText`, `setTextColors`), over upstream's text
  editor background. The comments field is multi-line, with Return
  starting a new line, and holds 500 characters (`kMaxCommentLength`).
  Return in the name or author field saves.
- Turning a style button on turns the others off (`buttonClicked`). The
  buttons are editor-local values (`SAVE_STYLE_BUTTONS`).
- `save`:
  - A blank name does nothing.
  - The file is `<name>.<extension>`, made legal by `legal_file_name`
    (`File::createLegalFileName`).
  - An existing file asks "Overwrite existing file?" first.
  - A preset remembers the author in the config (`saveAuthor`), sets the
    synth's author, comments and style with `"` removed, and is written by
    `save_preset_file`.
  - A wavetable is its JSON with `"name"` and `"author"` set.
- A click outside the save box closes the section (`mouseUp`), in either
  mode, as upstream's tests `getSaveRect` both times.
- After a save the preset browser reads its presets again and the header's
  `*` clears. Both happen for a wavetable too, because upstream's preset
  browser and header listen to every save (`PresetBrowser::save`,
  `HeaderSection::save`).
- Presets go to the user's Presets folder (`user_folder`, G7a) and
  wavetables to its Wavetables folder, made if missing
  (`FullInterface::saveWavetable`). Upstream's are under a `User` folder
  inside the data folder. G7a's user folders have no such level, and the
  chat's preset tools share them. D24 now says so, and says that an
  upstream data folder's `User/…` content still shows up as a bank
  (`user_folders::directories`).

**Opening it**

- The header's save button and a new "Save Preset" menu item, second as
  upstream's (`SynthPresetSelector::savePreset`).
- An oscillator's wavetable view now offers "Save to Wavetables"
  (`save_available`), and its request (`take_save_request`, from #137)
  opens the section for that oscillator's wavetable.
- While the section shows, the preset browser behind it takes no keys, so
  the arrows move the name's caret instead of the browser's selection.
  Upstream gets this from keyboard focus.

**Shared pieces**

- `controls::text_editor`: `single_line_styled` (a font size and text
  colour), `multi_line`, and `focus_at_end` beside `focus_select_all`.
- `EditorModel`: `preset_style`, `set_preset_info`, `default_author` and
  `save_default_author`. The plugin keeps the author in its config beside
  `data_directory` (`config::author`, `config::save_author`).

**Harness**

- `ref-gui --overlay save_section` opens the save section for a preset
  without `SaveSection::setIsPreset`, which would make the user's preset
  folder inside the corpus data folder. `views.json` has a `save_section`
  view, and the gallery opens it through `Interface::request_save_preset`.
- `layout_paths.txt` checks the save section's parts at every size.

**Tests**

- `save_section` unit tests: the preset box against the layout dump, and
  `legal_file_name`.
- `tests/layout.rs`: the save section's paths at every fixture size.
- `tests/preset_selector.rs`:
  - the save button saves a named, styled preset with an author and
    clears the `*`;
  - "Save Preset" opens the section;
  - an existing name asks before overwriting, and Return saves;
  - a blank name doesn't save, and a click outside closes the section;
  - "Save to Wavetables" writes the wavetable with its name and author;
  - the browser takes no keys while the section shows.
- `sas-plugin` `a_saved_preset_carries_its_author_comments_and_style`, and
  `config::the_author_round_trips`.
- `test_gui_reference.py`: `test_the_save_section`.
- `sas-preset` `an_upstream_user_folder_is_found_like_a_bank`: an upstream data
  folder's `User/Presets`, `Wavetables`, `Samples` and `LFOs` are found.

No audio change.

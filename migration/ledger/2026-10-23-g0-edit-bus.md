## 2026-10-23: G0 edit bus, document mirror and allocation-free audio path

First of the G0 PRs (GUI plan, milestone G0). The editor (G1+) and the chat
layer (L4) change the playing synth through this bus instead of replacing
the whole preset. The live-edit parity case (`ref-render` edit script) and
the telemetry snapshot follow in separate PRs.

**Changed**

- `sas_engine::edit_bus` (new):
  - `EditBus::new(document) -> (EditHandle, EditConsumer)`. `EditHandle`
    is cloneable, `Send` and `Sync`, for the editor and the chat worker.
    It connects and disconnects modulations, sets remap curves, LFO shapes,
    wavetables (rendered on the caller's thread) and the sample, and runs
    all-or-nothing batches.
  - One bounded lock-free multi-producer queue (`crossbeam-queue`
    `ArrayQueue`, 256 entries; MIT/Apache, already in the tree through
    nice-plug), drained at the start of each block.
  - One pending slot per shape target (8 LFOs, 64 curves, 3 wavetables,
    the sample), newest wins. A heap-free marker in the queue keeps each
    one ordered against connections.
  - A return queue: the audio thread swaps prepared values in and hands
    the replaced ones back, so it never frees.
  - Generation tags: a host restore or preset load (`begin_restore`)
    bumps the generation, and entries queued before it are dropped. The
    restored document reaches the audio thread through its own slot, so
    the mirror lock is never taken there.
  - The mirror of the `PresetDocument` is updated with each edit, so the
    host saves edits without a reload. `revision()` moves on every change
    and `generation()` on every restore. `wavetable(osc)` gives the editor
    the rendered table.
  - The consumer side is public and host-free:
    `EditConsumer::drain(&mut Synth)`.
- `sas_preset::PresetState::connect_modulation_from_gui(source,
  destination, SlotValues)`: upstream's drag-to-control path
  (`ModulationManager::modulationDraggedToComponent`). If the two aren't
  connected yet, it does `connectModulation`, then `initModulationValues`
  (linear curve, power 0), then `setModulationValues(amount, bipolar,
  stereo = false, bypass = false)`. An existing connection is left alone.
  It returns the slot and the new slot's host parameter changes (power,
  amount, bipolar, stereo, bypass). Without these, a reused slot kept the
  freed route's amount, stereo and bypass, so a new route could arrive
  bypassed and silent (Graph Reviewer, from #92).
  `SlotValues::dragged_to(info, value, bipolar)` computes upstream's drag
  values:
  - the amount runs from the control's position `p` in its range to the
    top, `max(1 − p, 0.25)`, or `max(min(1 − p, p)·2, 0.25)` when a
    modifier key makes the drag bipolar;
  - stereo and bypass are off.
  The mirror uses this function, and so will LLM Builder's offline session.
- `PresetDocument` moved from `sas_plugin::state` to
  `sas_engine::document` (still re-exported) so that `sas-gui` and
  `sas-llm-control` can use the bus without depending on the plugin.
- Plugin: `SynthParams` holds the `EditHandle` (its document mutex and
  generation counter are gone), `BlockProcessor` owns the consumer, and
  `Engine::apply_edits` applies edits after the block's restore or
  parameter changes. `SynthPlugin::edit_handle()` hands the bus out.
- Swap primitives that act as an in-place edit would (no allocation):
  - `LineGenerator::take_shape` (the editor edits the shared model and
    calls `render()`);
  - `Wavetable::take_rendered` (the version moves on only when the frame
    count changes, as `setNumFrames`, so oscillators reset exactly when
    rendering in place would reset them);
  - `Sample::from_buffers` (no white-noise default, so no seed is taken
    from the global counter) and `Sample::swap_loaded`.
- `Synth`: `set_line_mapping`, `set_lfo_shape`, `swap_wavetable`,
  `swap_sample`.

**Audio-thread allocations removed** (structure only; no arithmetic or
order changes). Upstream doesn't allocate at any of these sites; the port
did, with clones made to satisfy the borrow checker:

- per block:
  - both `status_outputs` maps were cloned (`SoundEngine`,
    `SynthVoiceHandler`);
  - the voice handler collected the active aggregate voices and the voice
    killer's buffer into fresh `Vec`s;
  - the enabled modulation connections were collected when no voice
    played;
- per MIDI message: 16 voice-handler loops (sustain, sostenuto, all notes
  off, aftertouch, slide, pitch bend) collected `active_voices` into a
  `Vec`; they walk it by index now (none of their bodies edits it);
- per parameter change: `Synth::set_control` rebuilt the whole control map
  (`get_controls`); `Synth` now keeps it from construction;
- on effect enable/disable: `enable_owned_processors` cloned its lists;
- connection bookkeeping: sub-module lookups (`get_modulation_source`,
  `get_*_modulation_destination`, `get_*_modulation_switch`,
  `get_status_output`) cloned the sub-module list. Bank slot names were
  re-allocated; they now reuse 64-byte strings, which hold every source
  and destination name (asserted in a test). `createConnection`'s
  `"modulation_N_amount"` check formatted a string. The modulation change
  queue lost its capacity on every drain.

**Tests**

- `engine/tests/edit_bus.rs`:
  - order of arrival;
  - refused edits change nothing;
  - coalescing (100 drags of one LFO apply once);
  - a curve set after a created connection lands after its linear reset;
  - a reused slot doesn't inherit the old route's amount, stereo, bypass or
    power;
  - a restore drops older edits and holds newer ones until it is loaded;
  - batches roll back on an error or a full queue;
  - a full queue refuses without touching the mirror;
  - the editor's rendered wavetable is shared and re-rendered after a
    restore;
  - **bus edits play bit for bit like in-place edits**: a connection,
    remap curve, LFO shape, multi-frame wavetable and sample sent over the
    bus, against the same edits made on the engine as upstream's editor
    makes them (`connectModulation`, `jsonToState`, `render` into the
    engine's table, `loadSample`). 400 blocks with notes; the first
    differing sample is none.
- `plugin/tests/edit_bus.rs`: edits made on `SynthPlugin::edit_handle()`
  plus the host parameter changes they report play bit for bit like the
  same edits made on `Synth` directly; the host saves the edited state; a
  host restore drops a connection queued before it, so the output equals a
  render without it.
- `engine/tests/edit_bus_no_alloc.rs` (a counting global allocator; each
  run takes 4000 blocks while a producer thread edits):
  - Shapes, curves, wavetables, samples, batches and restores on presets
    without modulation routing, where nothing rewires the graph. Each whole
    block is counted: the drain, parameter changes, notes, sustain, bends
    and pressure, at four block sizes. **0 allocations and 0 frees.**
  - Connections and disconnections every round, plus batches: the drain
    and `Synth`'s connection bookkeeping are counted. **0 allocations and
    0 frees.**
  - Left uncounted, because upstream allocates there too: the
    whole-document load of a restore (upstream loads presets with
    processing paused) and the graph rewiring of a connection
    (`process_modulation_changes`, and the routers' order updates it
    triggers in later blocks; upstream's `plugNext`, `connect` and
    `updateAllProcessors` allocate). Parked as I14 in IMPROVEMENTS.md.
- `plugin/tests/edit_bus_no_alloc.rs`: the plugin's whole
  `BlockProcessor::process` over 3000 blocks of four sizes, while an
  editor thread sends shapes, curves, wavetables and samples and the host
  moves parameters, toggles bypass and plays notes. **0 allocations and 0
  frees.**
- `preset/tests/api.rs`: `gui_connect_initializes_a_new_slot_only`
  (including a reused slot) and `a_drag_amount_follows_the_control_position`;
  `modulation_bank` unit tests (`is_own_amount` against the formatted
  name; slot name capacity).
- With no edits nothing changes: every existing test, all parity tests
  included, passes unchanged.

**Decisions**

- Amount, bipolar, stereo, bypass and power stay host parameters (set
  through `GuiContext`). Upstream's GUI sets them on the engine
  (`valueChanged`) and only updates its own sliders. Here the host
  parameters are the saved state, so `Connection::parameter_changes` tells
  the caller to set them, and the saved state matches upstream's. The host
  is notified of these values, which upstream doesn't do; there's no
  engine change, so no divergence entry.
- On the engine, the connect edit sets only the new slot's polarity, right
  after `createConnection` sets the source's default
  (`Synth::gui_connect_modulation`). Amount, stereo, bypass and power arrive
  only as host parameters. The bus and the host parameters are two
  unordered channels, and the plugin applies parameters first in a block,
  so writing those values from the edit as well could override a value the
  host changed in the same block. A host-free caller applies
  `parameter_changes` with `Synth::set_control`.
- An edit applies at the start of the next block, before its MIDI.
  Upstream's editor writes the shared engine at any time, and its
  modulation changes are applied at the next block as well, so a block
  boundary is upstream's own granularity for these edits.
- Coalescing, batch commit flags and the API were agreed with GUI Builder
  and LLM Builder (store: `internal/edit-bus-api-sketch.md`).
